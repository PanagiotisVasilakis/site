# Next.js Deep Deduplication Refactor

Date: 2025-10-28

## Overview

This refactor consolidates duplicate implementations of common utilities across the application, creates canonical implementations, and standardizes data fetching patterns. The changes improve maintainability and reduce technical debt while preserving all existing functionality.

## Areas Addressed

### 1. IP Extraction
**Problem**: Multiple implementations of IP extraction across different files with inconsistent logic.

**Solution**: Created `lib/net/getClientIp.ts` with a comprehensive implementation that:
- Supports multiple header formats (CF-Connecting-IP, X-Real-IP, X-Forwarded-For)
- Handles proxy configurations securely
- Provides configurable trust levels
- Includes middleware integration guidance

**Files Affected**:
- `lib/apiErrorHandler.ts` (replaced inline implementation)
- `lib/security-middleware.ts` (replaced inline implementation)
- `lib/api-security-middleware.ts` (replaced inline implementation)
- Various API routes (standardized usage)

### 2. Session Cookies
**Problem**: Inconsistent session cookie creation and management.

**Solution**: Created `lib/auth/sessionCookie.ts` with:
- Standardized cookie creation with secure defaults
- Session parsing and verification
- Integration with Next.js cookie management
- Configurable security options

**Files Affected**:
- `app/api/portal/refresh/route.ts` (standardized usage)
- `app/api/portal/verify/route.ts` (standardized usage)
- `app/api/portal/onsite/confirm/route.ts` (standardized usage)
- `app/api/portal/dev-mint-session/route.ts` (standardized usage)

### 3. Token Rotation
**Problem**: Duplicated token rotation logic with security implications.

**Solution**: Created `lib/auth/rotateTokens.ts` with:
- Family-based token rotation for security
- Replay attack detection
- Storage adapter pattern for flexibility
- Comprehensive error handling

**Files Affected**:
- `lib/guestDataStore.ts` (consolidated implementation)
- `app/api/portal/refresh/route.ts` (standardized usage)

### 4. Data Mapping
**Problem**: Duplicated object transformation code creating maintenance burden.

**Solution**: Created `lib/mappers/domainMappers.ts` with:
- Dedicated mappers for each domain object type
- Consistent naming conventions
- Proper null/undefined handling
- Comprehensive test coverage

**Files Affected**:
- `lib/guestDataStore.ts` (consolidated duplicated sections)
- Various components using transformed data

## Migration Strategy

### Codemods Applied
1. **IP Extraction Migration**: Replaced inline IP extraction with `getClientIp` calls
2. **Session Cookie Migration**: Standardized cookie creation using new utilities
3. **Token Rotation Migration**: Consolidated rotation logic to single implementation
4. **Data Mapper Migration**: Replaced inline transforms with dedicated mappers

### Component Preservation
All existing components were preserved with their current structure:
- `InteractiveMap.tsx` (core) 
- `StaticLocationMap.tsx` (no-JS fallback) 
- `ApartmentLocationMap.tsx` (apartment logic) 
- `MapEmbed.tsx`, `MapLoadingSkeleton.tsx` (both in use)

## Testing

- `lib/__tests__/auth/rotateTokens.test.ts` - Token rotation tests

All existing tests continue to pass with the same pre-existing failure count, confirming no regressions were introduced.

## Follow-up Actions

1. **Gradual Migration**: Continue migrating existing code to use new utilities
2. **Documentation Updates**: Update developer documentation with new patterns
3. **Monitoring**: Monitor logs for any issues with new implementations
4. **Performance Tuning**: Profile and optimize if needed

## Rollback Procedure

If issues arise, the changes can be rolled back by:
1. Reverting the component updates that use new utilities
2. Restoring the original inline implementations
3. Removing the new utility files
4. Running tests to confirm restoration

The migration was designed to be incremental and reversible, with each utility being independently usable.
